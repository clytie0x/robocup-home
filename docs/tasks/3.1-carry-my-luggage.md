# 3.1 Carry My Luggage

โครงเกณฑ์รับของงานนี้เท่านั้น ยังไม่ใช่กฎ RoboCup ฉบับทางการ
ยังไม่วิจัยกฎ จึงไม่มีการอ้างว่าสอดคล้องกับกฎ และยังไม่มีคะแนน บทลงโทษ เวลา หรือเงื่อนไขที่ใช้ได้

ชื่อและเลข 3.1 มาจากคำบรรยายใน `README.md` ของคลัง ไม่ได้มาจากการตรวจกฎในไมล์สโตนนี้

## ยังไม่ตรวจ

ช่องต่อไปนี้เป็น TODO ทั้งชุด จนกว่าจะมีแหล่งกฎที่ตรวจแล้ว

| หัวข้อ | สถานะ |
| --- | --- |
| ฉบับกฎ (rulebook edition) | ยังไม่ตรวจ |
| เงื่อนไขเริ่ม ทำสำเร็จ และล้มเหลว | ยังไม่ตรวจ |
| คะแนน | ยังไม่ตรวจ |
| บทลงโทษ | ยังไม่ตรวจ |
| เวลาจำกัด | ยังไม่ตรวจ |

ห้ามเติมตัวเลขหรือเงื่อนไขจากความจำแล้วปิดช่องเหล่านี้

## โครงเกณฑ์รับ

แต่ละเงื่อนไขที่มาจากแหล่งต้องมีหนึ่งแถวในตารางสอบกลับก่อนมีโค้ด
ตอนนี้มีเพียงแถวที่บันทึกว่าแหล่งยังว่าง ไม่มีแถวเงื่อนไขทางการ

| requirement | source | test | result | gate |
| --- | --- | --- | --- | --- |
| ฉบับกฎ เงื่อนไข คะแนน บทลงโทษ และเวลาของ Carry My Luggage | ยังไม่มีแหล่งที่ตรวจแล้ว | ยังไม่มี คำสั่งยังไม่รัน ซีดจำลองยังไม่มี | unverified | unspecified |

ความหมายของผล: `unverified` ยังไม่มีแหล่งหรือยังไม่ตรวจ, `not-run` มีแหล่งแล้วแต่ยังไม่ได้รัน, `pass` และ `fail` ใช้เมื่อมีผลคำสั่งจริงเท่านั้น
`unspecified` หมายถึงยังไม่รู้ว่าเงื่อนไขอยู่ชั้น sim หรือ hardware ห้ามตีความเป็น pass ของชั้นใดชั้นหนึ่ง

## จำลองกับฮาร์ดแวร์

- แถว `sim` ทดสอบบนแล็ปท็อปหรือแบบจำลองได้ เมื่อมีแหล่งและคำสั่งที่รันจริง
- แถว `hardware` ปิดไว้ จนกว่า Teerapat จะอนุญาตในงานนั้น เอกสารนี้ไม่มีขั้นตอน deploy หรือ flash
- ผลบนแบบจำลองไม่ปิดแถวฮาร์ดแวร์
- ห้ามเขียนว่าผ่านทุกเงื่อนไขถ้าตารางยังไม่ครอบคลุมเงื่อนไขที่มีแหล่งครบ หรือยังมีผลที่ไม่ใช่หลักฐานจริง

## เมื่อจะลงมือครั้งถัดไป

ทำหลังวิจัยกฎฉบับทางการและงานที่มีมาก่อนเท่านั้น

1. เติม source ของแต่ละ requirement จากกฎที่ตรวจแล้ว ข้อที่ยังไม่มีแหล่งคงเป็น unverified
2. เขียนเทสต์แดงก่อน สำหรับเงื่อนไขนั้น รวมเคสที่ควรล้ม เคสขอบเขต และซีดจำลองที่ทำซ้ำได้
3. ค่อยทำให้เขียว แล้วจัดรูป แล้วบันทึกคำสั่งกับผลลงคอลัมน์ test และ result
4. แยกชั้นทดสอบเป็นหน่วย สถานการณ์จำลอง และสัญญาของ adapter ตาม `AGENTS.md`
