Result meanings: `unverified` has no source or has not been checked; `not-run` has a source but has not been run; `pass` and `fail` are used only with a real command result.
`unspecified` means the layer is not yet known to be sim or hardware. Do not treat it as a pass on either layer.

## Simulation and hardware

- A `sim` row can be tested on a laptop or in simulation once it has a source and a command that was actually run.
- A `hardware` row is not passed while that task's device is not authorized and connected. Jetson, arm, and Pi stay untouched until then.
- Deploying and flashing are not categorically forbidden. This file still contains no deploy or flash steps, because no device is connected and this milestone is documentation only.
- A simulation result does not close a hardware row.
- Do not write that every condition passed unless the table covers every sourced condition and every such result is real evidence.
