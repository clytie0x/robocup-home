# Saved camera archive

This slice reads the measured 39-frame `camera.npz`. It does not call `cast_pixel`, `controller_note`, or a task crate. It does not write `RCF1`. A decoded archive is not a fresh observation, not a device clock, not a registration, and not a person. Stage 4 is not complete. Stage 5 is not complete.

## How to run

From the repository root, with the pinned toolchain:

```text
cargo run -p physical --bin camera-archive --locked --offline -- CAMERA.NPZ
```

Exit 0 prints one summary line and 78 frame-hash lines: 39 colour and 39 depth. The summary gives the three payload lengths, the three payload SHA-256 values, the count of distinct frames, and the first and last stamp. Exit 1 is a read or decode error. Exit 2 is a usage error. The program does not print a pixel.

`--compare` reads a framed independent decode on stdin. The frame is the four bytes `NPZ1`, then three sections. Each section is a little-endian `u16` name length, the name `rgb`, `depth`, or `stamps`, a little-endian `u64` byte length, and that many bytes. A mismatch prints the section name and the byte offset. A match prints `compared=yes match=yes`.

The file and that frame are read by `read_file_bounded` and `read_bounded`. The file ceiling is the three documented compressed sizes 5561734, 1002834, and 342, plus the three zip64 local headers (59, 62, and 65), the three central headers (55, 58, and 61), and the 22-byte end record: 6565292. The frame ceiling is `NPZ1` plus the three exact payloads 8985600, 5990400, and 312, with each section's 2+name+8 header: 14976360. One byte past either ceiling is `input bound limit=N`. That byte is not kept, and the rest of the stream is not read. A declared section length other than those three payload sizes is rejected before the payload is copied. A declared length that matches, with too few bytes present, is a truncated payload. The error text is the bound or the section name. It does not include payload bytes. The inflater caps, 8985728 and 230640, are unchanged.

## What the file is

The plan in [WORKLOG.md](../../WORKLOG.md) measured one archive. SHA-256 `d3319c4f0e8a5ffc7f65fb3c0f7dd9a9a992a5874c0297b9e8b0a4e5d7895c9a`, 6565292 bytes. Three members, in order: `color.npy`, `depth_mm.npy`, `t_monotonic.npy`. Each local header is version 45, flags 0, method 8, and both 32-bit sizes are `0xFFFFFFFF`. The zip64 extra is id `0x0001`, length 16. The resolved uncompressed sizes are 8985728, 5990528, and 440. The central headers store those sizes as 32-bit fields and have an empty extra. There is no data descriptor, no ZIP64 end record, and no ZIP64 locator.

The compressed bytes are raw deflate ([RFC 1951](https://www.rfc-editor.org/rfc/rfc1951)), not zlib-wrapped ([RFC 1950](https://www.rfc-editor.org/rfc/rfc1950)). ZIP CRC-32 covers the inflated bytes. Each inflated member is NumPy 1.0. Colour is `|u1`, C order, shape `(39, 240, 320, 3)`. Depth is `<u2`, C order, shape `(39, 240, 320)`. Time is `<f8`, C order, shape `(39,)`. The layouts are ZIP local headers and the zip64 extra in APPNOTE 6.3.10, and the NumPy 1.0 header.

`inflate_raw_capped` reuses the private block decoder and refuses a cap above 8985728. `inflate_capped` still requires the zlib header, the Adler32 trailer, and the still-image cap of 230640. `zip_entries` still stops on method 8 and on `u32::MAX`. No ZIP crate was added.

## The buffers

`read_camera_npz` returns 8985600 RGB bytes, 2995200 little-endian depth words, and 39 finite stamps. The stamps must strictly increase. Index `frame * 240 * 320 + row * 320 + col` is that pixel, with three channel bytes for colour. The reader does not write a file.

The walker rejects a short header, a flag other than 0, encryption, a data descriptor, a method other than 8, a size other than the three exact lengths, an offset that overflows, a duplicate name, a different order, an unknown name, a fourth member, a gap, an overlap, a trailing byte, a truncated file, a CRC mismatch, a central field that disagrees, a central zip64 extra, a multi-disk end record, a ZIP64 end record, and a ZIP64 locator. After inflate it rejects a NumPy major other than 1 or a minor other than 0, Fortran order, a wrong descr, a transposed shape, a byte after the payload, a non-finite stamp, and a stamp that does not increase.

## What this does not claim

The stamps are the host monotonic samples of the throttle. `record_static.py` line 12 samples `time.monotonic()`, line 42 sleeps 2.6 s, line 43 samples it again, and lines 47 to 52 append a sample only when 0.35 s has passed. `person.py` lines 191 to 205 declare `Frame.ts`. Lines 234 to 247 copy width, height, RGB, and millimetre words, and they do not copy `ts`. Colour channel order follows the writer's `rgb` name. No colour chart was measured. Mirror, field of view, and the two mounts stay the frozen pinhole values. The constant odometry pose is a third pose. The pose note for this recording still says not to register it to the course map. Section 3.1 stays 45 pass and 11 not-run. Stage 4 is not complete. Stage 5 is not complete.
